# Owner-only comparison after both benchmarks terminate

This is not mathematical input for either measured arm. Neither construction
task reads the sibling benchmark or writes this comparison. The coordinating
owner uses this plan after both selected runs are terminal, their exact owned
processes/groups have exited and no authorized continuation remains pending.
Preparation is not a completed experiment; do not create invented result rows.

## Scope and output

Compare the newly authorized V1 run under `../benchmark/results/<run-id>/` with
the new V2 run under `results/<run-id>/`. Bind the two exact run IDs, thread IDs,
source/runtime hashes and input hashes. Write `comparison.json` and
`comparison.md` in this directory after termination. The retained direct-model
attempt is historical context only, not a newly executed matched third arm.

## Required checks and report

1. Confirm equal original PDF bytes, complete selected target and initial
   mathematical inputs, requested phase profiles, worker counts, native limit
   and total-budget policy. Record actual deviations instead of normalizing them
   away. Treat each selected skill's internal procedure as the intended variable.
2. Read real terminal case-result/completion files and linked A, interface,
   assembly, native trust and B reports. Validate existing bound artifacts with
   each run's bound validators without another model/proof run. Do not relabel
   V1 receipts as V2 or infer B from compilation. Report target and every external
   theorem correspondence and every inaccessible-source warning separately.
3. Confirm actual per-run process/group exits with PID, OS start and PGID. Keep
   stopped/faulted/conditional runs in the comparison; an incomplete experiment
   has a result status, not a fabricated successful completion.
4. Include dispatch/terminal timestamps, total elapsed wall time, NL0 author,
   Audit A, translation preparation/interface review, local proofs,
   assembly/native and B times where recorded. Distinguish overlapping worker
   work from elapsed wall time, and report missing breakdowns as unknown.
5. Include distinct-response input/output/total tokens, cached/reasoning subsets,
   usage coverage, owner overhead separately, and all repair/retry/continuation
   costs. Missing tokens are not zero; no character estimates become exact usage.
6. Record requested/observed model, effort and service tier, actual concurrency,
   execution faults, no-progress/timeout incidents, source retrieval outcomes,
   repair effectiveness and any warm reuse. Do not attribute software faults
   solely to model capability or discard failed attempts.
7. Summarize whether V2 reduced preparation/A costs, moved work into translation,
   changed correspondence quality or introduced new blockers. Support each
   observation with exact artifact references. One concurrent pair, with shared
   host/account and external website variability, does not prove causal speedup,
   general superiority or held-out benchmark performance.

Keep comparison files out of construction input manifests. The final human
report should link both final outcomes and this comparison, state actual A/B
acceptance and qualifications, and explain any incomplete measurement.
