# Writing Lean from a frozen informal argument

## Question and experimental contract

Can local proof revision reduce the work needed for the first checked proof with the same model, relative to full-body resubmission? Can an actual consumer application expose a shared representation defect before proof writing? This pilot uses the committed Yui e28cc34f behavior as the baseline. It starts after interface freeze, and also runs a separate falsifier at the interface boundary. The frozen foundation, NL route, statements, direct input binders, Lean and Mathlib are fixed in a paired writing trial. No complete Lean proof is supplied.

Record acceptance, actual model/effort, tokens and elapsed time. Preserve nonpasses and report the reason. Verify accepted bodies again using the ordinary native checker. Archived candidate sequences are used for exact counterfactual payload comparisons only. Their sizes cannot establish live model savings or proof search quality. Small paired trials are exploratory and support no universal speedup claim.

## Candidate routes

| Route | Mechanism | Falsifier and decision |
| --- | --- | --- |
| Enumerate all concepts before translation | Resolve inconsistent representations globally from a conceptual dependency graph | Two type-correct statements can still be incompatible at their actual use. Reject a second meaning registry requiring full coverage. Reuse the existing global definitions, object views and input instances. |
| Validate selected consumer uses before body writing | For a shared or representation-sensitive interface, elaborate the actual application or projection against the expected type in the consumer context | Correct and incorrect consumers must receive different outcomes with their endpoints unchanged. If the representation discrepancy is mathematically semantic, a type check cannot certify fidelity. Keep source-based review. |
| Revise a retained proof draft at the first concrete error | The tool reconstructs the exact old candidate with one checked literal replacement. Lean checks the full reconstructed body using the normal path. The author can also submit a saved body | Compare initial proof plus edits with full submissions along identical candidate trajectories, and compare fresh actual model runs. A changed frozen assumption, duplicate anchor, or unresolved Lean goal must still be rejected. |
| Cache elaborated proof prefixes | Use a pinned Lean environment to check a changing suffix while reusing unchanged declarations | This can reduce Lean time without changing authoring. Yui already caches auxiliary modules. Keep this as a separate experiment that would require equivalence tests for typed ports, instances and tactics using ambient declarations. |

Closest prior art is [LeanFlow](https://arxiv.org/html/2607.20503) for declaration-local history and LeanProbe, [ToMap](https://arxiv.org/html/2607.11307) for testing which layer to repair, [ProofFlow](https://arxiv.org/html/2510.15981) for explicit proof dependencies, and [MechMath](https://mechmath.github.io/publication/mechmathv1/) for reusing partially successful proof structure. A general Lean tactic-state editor and a new concept graph would require separate cost and scope justification.

[BlueprintRepair](https://aclanthology.org/2026.mathnlp-main.3/) already compares schema-typed graph edits, exact source patches and whole-module rewrites with a fixed model. The editable unit in this pilot is the proof body *after* semantic interface freeze. [ProofPatch](https://arxiv.org/html/2611.01357) also distinguishes a typed declaration from the statement intended by its source, and tracks scope through dependencies of elaborated terms. Neither the use-site idea nor submitting source patches is a claim of general novelty.

The methodology is a bounded local pilot in the deepening style. Research Cognition selected no expert or reusable method for Lean proof engineering. The caller-assisted abstention, scope binding and empty selection are retained in route-receipt.json. This is a software and model experiment, with no remote compute dispatch. The local native model provider is used through Yui's existing carrier.

## Method

1. Pick representation choices where they affect a direct proof application. Fix the shared definitions in dependency order and retain the original foundation signatures. Use existing object views to document legitimate distinct representations. A concept can be shared across branches and can depend on several earlier choices.
2. For a shared or representation-sensitive edge, construct an actual application in its consumer context with the expected type, including relevant arguments and side conditions. Reuse Yui's existing type probes or input instances. The source reviewer must still verify that it is the needed application. A contract that elaborates in isolation admits both a short horizon and a long horizon. A consumer check can distinguish substitutability at the use. The economics favor these probes where one wrong shared choice can waste work across many consumers. An inventory of every symbol incurs preparation cost even at low-risk uses.
3. Start a proof with the frozen local NL steps and exact direct inputs. Repair the first relevant failed body location with one exact edit to the saved draft when the surrounding route is useful. Reconsider the route with a new complete body if a local change does not suffice. A successful auxiliary proof stays a checked conditional theorem over the original local context. Return a repeatable statement or representation defect to interface review with the source, expected application and Lean evidence.
4. Always run the ordinary checker on the reconstructed body and the ordinary final assembly and audit for production cases. A diagnostic check or the use-site product never supplies new hypotheses. Bind results to the exact retained draft and full check.

Under the same context, the reconstructed text is identical to the specified full candidate. This gives a checkable equivalence at the input of the native checker. It gives no guarantee about a model choosing the useful edit or finding the proof. If a trajectory has whole bodies of lengths \(L_i\) and only small localized changes, the submitted text can scale with the first body and the old/new strings in subsequent edits. The cost still includes reading the current anchor, diagnosing the error and elaborating the resulting proof.

## Results and decision

**Concept representation.** The archived JSP-000175 T077 to T007 diagnostic identifies two distinct horizons. Its T077 predicate fixes the round count to `heightL0 n`, while the source use in T007 needs the squared logarithm. With the same archived header, both propositions elaborate as independently valid signatures. Applying the old premise at its original horizon passes. Applying it at the squared-logarithm horizon fails with a type mismatch located at T007 ← T077. The control with a premise of the expected internal type passes. This tests a projected use of the actual predicates. It establishes neither an implication between the two horizons nor a finished proof of either node. The result supports checking selected edges in addition to declarations and justifies keeping this gate before body authoring.

**Archive replay.** The tool could reconstruct each of 63 saved candidates exactly. For 34 candidates, one exact edit or a saved body was shorter. The total compact JSON request payload was 334,181 bytes for full bodies and 125,235 bytes after choosing the shorter request. After removing adjacent repeats, the totals were 302,079 and 125,026 bytes. Selection sees both successive candidates here and is a feasible hindsight comparison. T078 had no savings among changed bodies. Candidate validity, Lean check workload, actual model output and time-to-acceptance are separate quantities.

**Fresh fixed-model runs.** Every arm starts from the same frozen statements, local natural-language proof and direct inputs. There is one fresh native author per arm with GPT‑6.1 Sol, high effort and configured Standard speed. The per-arm wall budget is 220 seconds. The first arm varies by case. The timed author uses Mathlib and the same-node auxiliary checker. Graph-level child scheduling, semantic review and assembly are outside these timings. Runs overlap locally and timings have shared-host noise. All four accepted bodies passed a fresh native check with the standard axioms. Reading the proofs confirms the two geometry authors follow the source's dimension lower bound by letting the exponent increase to the dimension. Both Lie authors implement the two commutator inductions. The source readback concerns just these local steps.

| Local goal | Full-body control | Retained draft edit | Compact tool-argument bytes |
| --- | --- | --- | --- |
| Hausdorff product dimension T014 | Accepted in 67.098 s | Accepted in 79.088 s | 3,014 → 1,673 |
| Reduced Lie representation T001 | Accepted in 99.700 s | Accepted in 97.480 s | 6,444 → 2,729 |
| Wave-map energy T005 | Unfinished at 220.386 s | Unfinished at 220.442 s | 403 → 9,935 |

In the Lie case Lean located a type mismatch at draft line 55. One exact edit replaced the failed arithmetic normalization and kept the rest of the proof. The author submitted the new draft by number. The geometry author reused the first passing draft, and the edit arm took longer overall. In the wave case the edit arm continued to send full bodies while the differentiation applications changed, and neither arm passed within the budget. Both outcomes were attributed to model budget exhaustion by the carrier, with qualified input and no recorded execution fault. The native subscription usage ledgers were partial in all six trials. They do not establish a token comparison.

**Decision.** Retain typed consumer checks and local edits as small, compatible experiments on fast. These data establish one early interface failure and a concrete way to reduce repeated proof text. They leave an end-to-end speedup unverified. The strongest unresolved hypothesis is that more of the wasted work can be eliminated before script repair by detecting use-site defects while the relevant declaration can still be revised. A larger paired study would need cases sampled before observing which ones benefit, complete usage receipts, and a combined outcome for source fidelity and time to the first accepted body. A warm proof-check environment should be evaluated separately against native equivalence using long drafts and scoped instances.

The Yui fast implementation is `ad820863`. Its Lean quick scope passed 25 software tests, and the focused proof editing and input-instance controls passed 12 tests. Workflow Builder's before/after audit passed with the same public plan. [Measured trials, replay receipts and checks](results.json)

## Reproduction

Use an adapted experimental Yui worktree with the shared Lean 4.32.2 and Mathlib revision `905b95818eb32af7874a58b427f50c1711a5e96c`. Run the commands from this directory or pass the equivalent absolute paths. Each output directory is fresh.

- `python -B pilot.py --yui "$YUI" --plan "$PLAN" --step T014 --arm full --seconds 220 --out "$OUT/geometry-full"` runs one fresh author with the current baseline tool schema and a fixed model. Repeat with `--arm edit` and a new output path. The comparable plans are the archived conditional exercise `workflow/proof-run/inputs/plan.json` files in this repository. Only their source and frozen interface are read. Each accepted body is checked again by the ordinary checker.
- `python -B replay.py --yui "$YUI" "$WORKERS/T006" "$WORKERS/T036" "$WORKERS/T078" "$WAVE_WORKERS"` reproduces the archive comparison. The JSP worker root is the November 17 12:25:22Z run, translation 0001. The wave root is the recorded conditional exercise run of November 1. The script counts compact UTF-8 JSON request bytes, tries one adjacent-draft exact edit, and makes a byte-for-byte reconstruction check before selecting the shorter form.
- `python -B consumer_probe.py --yui "$YUI" --contract "$JSP_CONTRACT" --out "$OUT/consumer"` uses the JSP November 17 10:04:51Z run, translation 0002, proof-run input contract. The harness copies its exact Lean header, varies only the internal test binding, and calls Yui's actual typed-use renderer. It saves every generated Lean source and compiler result and requires the correct failure location.
